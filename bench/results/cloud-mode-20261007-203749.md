# figma-console-mcp Cloud Mode: reachability check

Date: 2026-10-07T20:37:49Z
Target version: v1.40.9 (README "Current Status" line, 2026-10-07)
Method: streamable HTTP, no real Figma credential, no plugin pairing

## What Cloud Mode is

Per the upstream README, Cloud Mode is a hosted MCP endpoint for web AI
clients (Claude.ai, v0, Replit, Lovable) that relays write commands over a
Cloudflare Durable Object to a paired Desktop Bridge plugin running in
Figma Desktop. It needs no local Node.js install, but it does need Figma
Desktop, the Desktop Bridge plugin paired once with a 6-character code, and
a Figma Personal Access Token (PAT) as a Bearer token.

Endpoint: `https://figma-console-mcp.southleft.com/mcp`
Auth: `Authorization: Bearer <figd_... PAT>`

## What was tried

Per the task constraints, no account was created, no plugin was paired,
and no real token was used. A placeholder `figd_dummy` stood in for a real
PAT, the same placeholder already used for the NPX measurement in
`tool-tokens-20261007-221725.md`.

```sh
curl -i -X POST https://figma-console-mcp.southleft.com/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{...}}'
# no Authorization header

curl -i -X POST https://figma-console-mcp.southleft.com/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "Authorization: Bearer figd_dummy" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{...}}'
```

## Result: blocked before tools/list

| Request | HTTP status | Body |
|---|---|---|
| No `Authorization` header | 401 | `{"error":"unauthorized","error_description":"Authorization header with Bearer token is required"}` |
| `Authorization: Bearer figd_dummy` | 401 | `{"error":"invalid_token","error_description":"Figma Personal Access Token is invalid or expired. Ensure your PAT (figd_...) is valid and has not been revoked."}` |

Both responses carry a `WWW-Authenticate` header pointing at
`/.well-known/oauth-protected-resource`, which returns an OAuth
protected-resource descriptor (scopes: `file_content:read`,
`file_versions:read`, `file_variables:read`, `file_comments:read`,
`file_comments:write`, `library_content:read`).

The endpoint validates the PAT before it accepts any JSON-RPC method,
including `initialize` and `tools/list`. There is no dummy-token or
no-auth path that reaches `tools/list`, unlike the NPX stdio server,
which lists its 121 tools with a placeholder `FIGMA_ACCESS_TOKEN`.

**Exactly what Cloud Mode requires before tools/list:** a valid Figma PAT
in the `Authorization: Bearer` header. (A paired Desktop Bridge plugin is
also required before any write tool call succeeds, per the README, but
that pairing step was not reached because the PAT check fails first.)

## Not measured

Tool count, exact bytes of `JSON.stringify(tools)`, approximate tokens
(o200k_base / cl100k_base), share of a 200K context, and median time to
`tools/list` could not be measured. Every one of these needs a live
`tools/list` response, which needs a real, valid Figma PAT. Creating or
using a real credential was out of scope for this check.

The README's own count for Cloud Mode (96 tools, vs 121 for NPX/Local
Git) is unverified by direct measurement; it is cited at
docs/comparison.md Sources as a vendor-stated figure, not a bench result.
